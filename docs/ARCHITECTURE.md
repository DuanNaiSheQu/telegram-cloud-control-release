# 系统架构概览

> 这是**概览级**说明 —— 讲清系统由哪几块组成、数据怎么流动。
> 具体的调度算法、账号策略与风控参数属于授权内容，见 [README](README.md#不在本仓库的文档)。

## 一句话

**两个进程 + 两个存储**：控制台前端连 API，API 把任务写进队列，Worker 取任务去操作 Telegram，结果回写入库，API 再推给前端。

## 组成

```
┌─────────────┐        ┌──────────────┐        ┌──────────────┐
│   前端控制台   │  HTTP  │   API 服务     │  SQL   │  PostgreSQL  │
│  (浏览器)     │ ─────▶ │  (FastAPI)   │ ─────▶ │  业务数据      │
└─────────────┘        └──────┬───────┘        └──────────────┘
        ▲                     │                        ▲
        │ WebSocket           │ 任务入队 / 事件发布         │
        │                     ▼                        │
        │              ┌──────────────┐                │
        └───────────── │    Redis      │                │
                       │  队列 · 订阅   │                │
                       └──────┬───────┘                │
                              │ 取任务                   │
                              ▼                        │
                       ┌──────────────┐                │
                       │    Worker     │ ───────────────┘
                       │ (Telegram 账号) │
                       └──────┬───────┘
                              │ MTProto
                              ▼
                       ┌──────────────┐
                       │   Telegram    │
                       └──────────────┘
```

### 各部分的职责

| 部分 | 做什么 | 不做什么 |
| --- | --- | --- |
| **前端** | 界面、表单、实时状态展示 | 不直接接触 Telegram |
| **API** | 鉴权、校验、把操作转成任务写进队列、推送实时事件 | 不执行耗时操作 |
| **Worker** | 认领账号、执行任务（发消息 / 加群 / 改资料等）、回写结果 | 不处理 HTTP 请求 |
| **PostgreSQL** | 账号、会话、消息、任务、审计等业务数据 | — |
| **Redis** | 任务队列、账号租约、实时事件发布订阅 | 不作为数据事实来源 |

## 几个关键设计

**为什么拆成 API + Worker 两个进程**
耗时操作（发送、加群）不能阻塞 HTTP 请求；拆开后 API 可以随时重启，Worker 独立运行、独立扩缩。

**为什么账号要「租约」**
一个账号同一时刻只能被一个 Worker 使用 —— 两个进程同时用一个账号会触发 Telegram 的会话冲突，严重时账号直接报废。租约机制保证互斥，Worker 异常退出后租约会超时释放。

**为什么任务队列支持"延后重试"**
被平台限流时不硬发，而是按建议时间重新入队 —— 硬发换来的通常是更长的封禁。

**数据放在哪**
全部在你自己的服务器上：PostgreSQL 存业务数据，Redis 存队列与实时状态，没有任何数据流向第三方。

## 部署形态

单机即可运行（API + Worker + 两个存储共 4 个进程）；任务量大时 Worker 可以多机部署，
但**每个账号仍只归属一个 Worker**。
